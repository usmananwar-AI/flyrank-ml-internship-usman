Workflow Walkthrough: Source-Grounded Study Notes Pipeline1. The Pipeline Sketch (Step Diagram)Goal: Convert raw academic materials into highly structured, reliable study guides without hallucinated math or code.Step 1: Gather (NotebookLM) - Upload raw PDFs, lecture slides, or textbook chapters into a dedicated NotebookLM study notebook.Step 2: Synthesize (NotebookLM) - Run a strict extraction prompt to isolate only factual definitions, core algorithms, and time complexities directly from the source.Step 3: Format (Claude/ChatGPT) - Pass the raw NotebookLM synthesis into a pre-configured Prompt Project to format it into clean Markdown tables, code snippets, and review questions.2. Configurations and Prompts UsedStep 2 Prompt (Inside NotebookLM):"Extract the core concepts from the uploaded documents. Do not use outside knowledge. Provide a raw list of: 1) Key definitions, 2) Algorithm steps or formulas, 3) Big-O time and space complexities. Include exact page/slide citations."Step 3 Prompt (Formatting Assistant):"You are an academic formatting engine. Take the following raw notes and format them into a structured Markdown study guide.Constraints:Use # for the main topic and ## for subtopics.Put all time/space complexities into a neat Markdown table.Format any mentioned code concepts into Python or C++ code blocks.End with 3 conceptual review questions based ONLY on the provided text."3. The Five Runs (Real Inputs)I tested this pipeline on my actual university coursework materials:Run 1: Circular Queues & Hash TablesInput: 45-page PDF slide deck on basic data structures.Output: A 2-page Markdown guide with a time-complexity table (O(1) for hash table lookups) and a cleanly formatted C++ circular queue array structure.Run 2: Binary & AVL TreesInput: Textbook chapter on tree balancing.Output: Extracted the exact balancing rotation rules (LL, LR, RL, RR) with source citations, formatted into a quick-reference cheat sheet.Run 3: Big-O Time Complexity BoundsInput: Lecture notes on asymptotic notation.Output: A clean table contrasting Big-O, Big-Omega, and Big-Theta definitions, plus 3 review questions on worst-case vs. average-case scenarios.Run 4: Database Normalization (1NF to 3NF)Input: Entity-Relationship modeling notes.Output: A step-by-step checklist for removing partial and transitive dependencies to reach Third Normal Form.Run 5: Relational AlgebraInput: SQL and relational database theory slides.Output: Formatted mathematical operators (Select, Project, Cartesian Product) mapped directly to their SQL equivalents.4. Time AccountingSetup Cost: 15 minutes to configure the NotebookLM workspace and dial in the formatting prompt constraints.Manual Time (per topic): ~45 minutes to read slides, pull out complexities, and type up formatted notes. (45 mins x 5 = 225 minutes).Pipeline Time (per topic): ~5 minutes to upload, run the two prompts, and copy-paste the markdown. (5 mins x 5 = 25 minutes).Total Time Saved: ~3 hours and 20 minutes (200 minutes) across the five runs, easily recovering the 15-minute setup cost.5. Known Failure Points & Human Review NeededMathematical Notation Loss: NotebookLM sometimes struggles to output complex mathematical symbols or relational algebra symbols (like sigma $\sigma$ or pi $\pi$) correctly in plain text. A human must manually verify math formulas.Over-Truncation: If a chapter is too long, the Step 2 extraction might summarize an algorithm too broadly, missing crucial edge-case steps.Formatting Hallucinations: The formatting AI in Step 3 occasionally tries to "fill in the blanks" for C++ code blocks if the original notes were pseudocode. A human must always review the generated code blocks for compile-ready accuracy.
